# 刀塔经理（Dota2 Manager）— 设计文档 v1

> 简介：接管真实豪门俱乐部，亦或白手起家打造护国之翼。训练、转会、新秀、BP 博弈、文字直播——让你的战队捧起不朽盾！

> 本文档是所有模块（引擎、数据、UI）的**唯一事实来源**。实现时如发现与代码骨架冲突，以 `src/engine/types.ts` 与各模块导出签名为准，并在本文档补充说明。
> 所有可调数值集中在 `src/engine/config.ts`，严禁在业务代码里写魔法数字。

---

## 0. 技术架构

| 层 | 技术 | 目录 |
|---|---|---|
| 模拟引擎 | 纯 TypeScript，无 React 依赖，可在 Node 下无头运行 | `src/engine/` |
| 静态数据 | JSON（真实战队/选手/版本/英雄/赛事），按 TI 懒加载 | `src/data/` |
| 状态管理 | Zustand（`game` + `version` 计数器，引擎原地修改 state 后 `version++` 触发渲染） | `src/store/` |
| UI | React 19 + Tailwind v4，中文界面，暗色主题 | `src/ui/` |
| 测试 | Vitest（引擎单测）+ `scripts/simulate.ts` 无头全流程模拟 | `tests/`, `scripts/` |
| 持久化 | localStorage 多存档位 + JSON 导入/导出 | `src/engine/save.ts` |

**引擎约定**
1. 引擎函数**原地修改**传入的 `GameState`（不做不可变更新），返回值只用于传递结果信息。
2. 随机数一律通过 `rngOf(state)` 取得（种子保存在 `state.rngState`），保证存档可复现。**禁止使用 `Math.random()`**。
3. 引擎内不得 import 任何 UI / store 代码。
4. 所有展示给玩家的文本为中文；选手 ID、战队名、英雄英文名保留原文，英雄另有中文名。
5. 金额单位为「金币」，整数；工资/费用随年代乘以经济指数 `econIndex(year)`。赛事显示真实奖金池（美元），实际发放按年代与等级压缩后的「游戏内奖金」（第五波，见 3.6）。

## 1. 时间模型

### 1.1 赛季与 TI
- 每个赛季以一届 TI 为终点，赛季用 TI 序号标识：`season.ti`。
- TI 序号 ↔ 年份：TI1=2011, TI2=2012, …, TI9=2019, **TI10=2021**（2020 因疫情停办，TI10 赛季横跨 2019-09 ~ 2021-10），TI11=2022, TI12=2023, TI13=2024, TI14=2025, TI15=2026, TI16=2027（未来，数据为推演）。
- 新游戏设定：起始 TI `startTi ∈ [1,15]`（需该 TI 的阵容数据存在），赛季数 `N ∈ [1, 16-startTi+1]`，终点 TI = `startTi+N-1 ≤ 16`。
- 起始阵容取「该届 TI 参赛时」的真实阵容（近似赛季初状态）。

### 1.2 大回合（Round）
每个赛季的日历在赛季初生成并**固定回合数**（`config.calendar.regularRounds`，默认 18）：

| 回合序号 | 阶段 `phase` | 说明 |
|---|---|---|
| 0 | `preseason` 赛季初 | 版本更新、新秀选秀（自动）、休赛期转会潮（AI 战队，见 7.1）、赛季状态、赛程公布、邀请函、转会窗口、报名赛事。玩家点「开始赛季」进入回合 1 |
| 1..R | `regular` 常规赛季 | 每回合要么是 **赛事回合**（玩家参加了该回合的某项赛事），要么是 **休赛回合**（训练/运营）。玩家未报名的赛事由 AI 在回合结束时后台模拟 |
| R+1 | `ti_qualifier` TI 预选赛 | 转会锁定。未获直邀的队伍打赛区预选；已获直邀的队伍此回合为休赛回合（可训练，不能转会） |
| R+2 | `ti` TI 正赛 | 转会锁定。只有 TI |
| — | `season_end` TI 结算 | 退役、年龄增长、合同、生涯记录（`legacyLog`）、赛季总结、检查游戏结束 → 进入下一赛季 `preseason` |

- 每个回合有日期区间 `[startDate, endDate)`，由赛季开始日（上届 TI 结束后约 2 周）到本届 TI 开始日线性切分。
- 真实赛事按日期映射到回合；同一回合可有多个赛事并行，但**玩家每回合最多参加一项**。
- 真实版本更新按发布日期映射到回合，在该回合开始时生效。

### 1.3 小回合（赛事内）
赛事回合中，玩家每一场系列赛（Bo1/Bo2/Bo3/Bo5）= 一个小回合：`赛前准备 → BP → 大老师胜率 → 文字直播 → 赛果`。系列赛中的每一局都有独立 BP 与直播。玩家可选择「快速模拟」跳过 BP/直播。同阶段其他比赛在玩家每个小回合结束后后台推进。玩家被淘汰或赛事结束后，剩余比赛瞬时模拟，弹出**赛事结算**。

## 2. 选手

### 2.1 属性（0–100 除注明外）
| 字段 | 含义 | 规则 |
|---|---|---|
| `age` | 年龄 | `season.year - birthYear` |
| `mmr` | 天梯分（数值，隐藏） | 显示为天梯等级 `tier` |
| `tier` | 天梯等级 C/B/A/S/SS/SSR | 阈值默认 `5000/5500/6500/8000/11000/15000`，`mmr ≥ 阈值` 即为该等级（<5000 也显示 C）。可配置 |
| `position` | 位置 C(1号位)/M(中单)/O(劣势路)/SS(4号位)/HS(5号位) | 打非本位置时战力 ×`config.team.offRoleFactor` |
| `power` | 战斗力（基础值，约 30–100，可超 100） | 训练/赛事/年龄/版本/事件改变 |
| `talent` | 天赋 | 决定成长随机区间的宽度（见 2.3） |
| `resilience` | 韧性 | **高韧性 = 事件对数值影响小**：影响系数 `1 - resilience/150` |
| `insight` | 灵性 | BP 阶段优势 |
| `loyalty` | 归属感 | 低则可能主动离队/被挖走 |
| `salary` | 每大回合工资 | 由等级、战力、年代经济指数决定 |
| `contractUntil` | 合同到期赛季（TI 序号） | 到期后成为自由选手（可续约） |
| `modifiers` | 临时/永久修正 | `{attr, kind:'add'|'mul', value, roundsLeft|null}`，`null`=永久；赛季状态也是一条修正（见 2.4.1） |
| `formTrend` | 隐藏趋势（-1..1） | 跨赛季延续的状态走势（第五波，`form.ts`），不在界面显示数值 |
| `salaryTrack` | 隐藏的薪资预期跟踪 | 近期冠军/MVP 热度、上回合薪资差、新秀合同标记（第八波，`salary.ts`） |

> 注：需求原文「低韧性对应事件对战斗力影响小」疑为笔误，采用常识方向（高韧性→影响小），系数在 config 中可反转（`config.player.resilienceInverted`）。

### 2.2 有效战力与天梯倍数
```
effectivePower(p) = (power + Σadd(power)) × Πmul(power)
ladderMult(tier)  = C 0.90 / B 0.95 / A 1.00 / S 1.05 / SS 1.10 / SSR 1.15   (config.ladder.multipliers)
playerRating(p, slotPos) = effectivePower × ladderMult × (slotPos===p.position ? 1 : offRoleFactor)
```
> 需求原文倍数「0.9、0.5、1、1.05…」中 0.5 疑为 0.95 的笔误，已按 0.95 实现，可配置。

### 2.3 成长（天赋 = 随机区间宽度，非线性）
**成长来源（成长重平衡，用户反馈 2026-10-09「成长性不高」）：训练是战斗力 / 天梯 / 灵性成长的主要来源（看天赋、花钱多）；比赛主要带来荣誉、金钱与韧性。**
一直训练的队员成长快得多（天赋越高越快），但每个休赛回合都加满额外训练与训练赛要花大量金钱；一直打比赛则基本只剩赛季初的自主成长（2.4.2），主要赚荣誉和奖金、磨炼韧性。

单次训练收益：
```
gain = U(min, min + spread × (talent/100)^talentExponent) × ageFactor(age) × focusMult × coachMult × scrimMult × softCap(current)
```
- 单次训练（`CONFIG.growth.training`：战力 U(0.05, 0.05 + 1.1 × t) / 天梯 U(10, 10 + 300 × t) / 灵性 U(0.03, 0.03 + 1.0 × t)，t = (天赋/100)^1.6）：
  天赋 75 的均值 战力 0.40 / 天梯 105 / 灵性 0.35（改动前 0.29 / 45 / 0.16），天赋 40 只有 0.18 / 45 / 0.15（下限保持原值，只放大幅度）。
  复核（2026-10-09）：首版单次 0.53 / 135 / 0.60 时，「不打可选赛事、只用每回合免费训练」就拿到绝大部分成长（新俱乐部狂练 95% 的训练是免费的），
  额外训练又贵得几乎没人买——单次收回约 1/4、额外训练降价，快速成长要靠花钱加练。
- **天赋 / 韧性按回合成长**（`CONFIG.training.extraSessionAttrMult` = 0.2）：年轻选手训练时的天赋自然增长与教练对天赋 / 韧性的提升，
  每个休赛回合的第一次训练（免费次数）全额，同一回合的额外训练 / 训练赛 / AI 加练只按 ×0.2 计——加练买得起之后，每回合 4 次训练会让（按公式）S 级教练一季提升
  20+ 天赋，低天赋新人被「练成」高天赋（同一 19 岁天赋 35 选手狂练 4 季：首版天赋 35 → 54，现 → 42~43），天赋不再决定成长快慢。
- 赛事成长（`growth.applyTournamentGrowth`，`CONFIG.growth.tournament`）：同一天赋随机公式 × 名次倍数 lerp(1.4, 0.6, 名次百分位) × 等级倍数 × 场次因子；
  战力 / 天梯 / 灵性约为改动前的 30%；新增**韧性**：U(0.2, 0.2 + 0.9 × (天赋/100)^1.6) × 名次压力 lerp(1.3, 0.7) × 等级（TI 2.0 / Major 1.4 / 顶级 1.2 / Minor 1.0 / 预选 0.7）× 场次因子 × 韧性软上限
  （天赋 70 的首发每项赛事约 +0.3，TI 冠军单项约 +1.4；只打比赛一季约 +5~6，约为狂练（只靠教练训练）的 1.6~2.3 倍——比赛是韧性的主要来源；结算弹窗、赛事页与荣誉史显示韧性成长）。
  复核：首版 U(0.06, 0.06 + 0.3 × t) 时只打比赛一季 +1.9，反而少于狂练的 +3.1。
- AI 战队的训练单独标定（`CONFIG.training.aiGainMult` 战力 1 / 天梯 0.92 / 灵性 1；加练次数 `aiExtraTrainingsPerRound` 富队 0.4 / 普通 0.1、
  `aiBusyExtraPerRound` 1.2：本赛季参赛比例越高、休赛回合加练越多），AI 首发的赛季内成长与改动前相当，联赛整体分布不随玩家训练加强而通胀（实测见 3.2）。
- `talentExponent` 默认 1.6（非线性）。`min` 固定，天赋只拉高上限 → 高天赋 = 高上限 + 高方差。
- `ageFactor`：≤19:1.25, 20–22:1.0, 23–24:0.8, 25–26:0.55, 27–29:0.35, 30+:0.2。
- `softCap`：战力越接近上限收益越小（`clamp((95.5-power)/20, 0.02, 1)`：85 → 0.53、90 → 0.28；`CONFIG.player.powerSoftCap*`），天梯、灵性同理各有软上限。
- 本赛季成长另 × (1 + 隐藏趋势 × `form.trend.growthWeight`)（爆发赛季 / 低迷赛季，见 2.4.1）；替补训练收益 × `benchTrainingMult`。
- 训练焦点 `focus`：`power` / `mmr` / `insight` / `balanced`（均衡 = 三项各 0.5 倍）。

### 2.4 年龄（每届 TI 结算时；第五波按现实规律重新校准，`growth.agePlayersAtSeasonEnd`，参数 `CONFIG.aging`）
- `age+1`（即 `season.year` 变化；TI10 赛季跨两年时按两年处理）。
- **位置巅峰窗口**：1/2 号位 21–25 岁、3 号位 22–26、4/5 号位 23–28（辅助巅峰更晚、更长）。过了巅峰之后训练/赛事成长 × `postPeakGrowthMult`。
- **巅峰后衰退是连续几个赛季的下滑，而不是断崖**：每赛季战力 −`base × y^exp`（y = 年龄 − 巅峰止，上限 `postPeakDeclineMax`）× U(0.7, 1.3) × 隐藏趋势倍数
  （1 号位 26 岁约 −1.1、28 岁 −3.0、30 岁 −4.7；辅助顺延 3 年）；天梯分同理温和衰减（每年 −70 × y'，上限 −400，避免某一季突然掉档）。
  ≥24 岁天赋每年 `-U(0,3)`；韧性 `+U(1,4)`、灵性 `+U(0.2,1.5)`。
- **退役**：年龄 > 25（按位置后移：3 号位 +1、辅助 +2）时按概率退役：`p = min(0.85, 0.06×(age-25-后移) + lowTierBonus) × lerp(1, 0.3, (基础战力-80)/10)`
  —— 仍保持高水准的选手较少退役（冠军队主力不会在巅峰末期集体退役）；退役选手按其天梯等级转为该等级教练（进入教练市场；若退役前在玩家战队，玩家获得优先签约权，签约费 0）。

#### 2.4.1 赛季状态与隐藏趋势（第五波，`form.ts`，参数 `CONFIG.form`）
- 每个赛季开始时：隐藏趋势 `formTrend ← 0.7 × 上季趋势 + 漂移 + N(0, σ)`（巅峰前高天赋选手正漂移、巅峰后负漂移，低迷/火热往往延续 2~3 个赛季）；
  赛季状态 = 战斗力 × N(1 + 趋势 × `trendWeight`, σ) 夹在 [0.93, 1.07]（σ 随韧性降低、对年轻选手放大），作为 roundsLeft = 本赛季回合数的修正存储，TI 回合结束时到期。
- 界面标签（火热 / 上升 / 平稳 / 低迷 / 挣扎）；赛季初为玩家战队发一条本队赛季状态简报。趋势同时放大/缩小本赛季的成长与赛季末的年龄衰减。

#### 2.4.2 赛季自主成长（第九波，`development.ts`，参数 `CONFIG.development`）
- 对应现实中选手的自主训练：每个赛季开始时（TI 结算的退役 / 年龄衰退之后、新秀选秀与休赛期转会潮之前，`season.startSeason → runSeasonDevelopment`），
  全体在役选手（首发、替补、自由选手、AI 战队选手；不含野外替补候选、退役 / 禁赛选手）各执行一次（`Player.development.ti` 防重复）；新游戏的第一个赛季不执行。随机数只用 `rngOf(state)`。
- **参照水平**：真实选手 = 真实生涯轨迹（`src/data/trajectories.json`）中「当届」的天梯 / 战力（相邻两届线性插值，如 Ceb 的 TI6–7 由 TI5 与 TI8 插值），
  永不超过真实生涯峰值 + 余量（+600 天梯 / +2 战力）；程序生成选手、真实选手最后一届真实数据之后、多人「选择已有战队」中被重置的真实选手（`development.noTrajectory`）
  = 隐藏潜力上限（首次评估时 = 当时水平 + 成长空间，之后固定；成长空间由天赋、距位置巅峰的剩余年数决定，越接近顶端越小）。
- **靠拢**（只升不越过）：低于参照时每季靠拢差距的一部分（真实轨迹：天梯 70%、战力 35%；潜力：天梯 40%、战力 30% × 年龄系数，已过巅峰为 0），单季至多 +2500 天梯 / +6 战力。
  战队选手的目标先扣除赛季内预期成长（训练 + 赛事，按年龄 / 首发或替补，`seasonAllowance`），使「自主成长 + 赛季内成长」≈ 当届参照水平；自由选手不扣除。
- **回落**：高于参照（同样扣除赛季内预期成长）+ 容差时回落超出部分的一部分（天梯是相对排名，人人上分即整体回落）：AI 战队与自由选手容差 100 天梯 / 0.5 战力、回落 85% / 70%；
  人类玩家战队容差 500 / 1.5、回落 70% / 60%（经理比 AI 多练的部分大多保留，可把选手推到轨迹之上一些）；单季至多 −1500 天梯 / −5 战力。
- **训练投入保护**（成长重平衡，2026-10-09，`CONFIG.development.investment`）：人类玩家战队训练获得的天梯 / 战力记入 `Player.development.trainedMmr / trainedPower`
  （`growth.trainTeam`，只记人类玩家战队），赛季初回落时其中 min(训练投入, 上限 × (天赋/100)^1.6) 不计入超出部分（上限 3000 天梯 / 6 战力：天赋 90 ≈ +2550 / +5.1、
  70 ≈ +1700 / +3.4、50 ≈ +1000 / +2、30 ≈ +450 / +0.9）——训练过的选手可以超出自身轨迹 / 潜力，天赋越高超出越多，练出来的提升大多保留；
  每个赛季自主成长之后训练投入 × 0.75（停止训练的选手，保护逐季减少）。AI 战队选手不受保护（转入 AI 战队后照常回落）。
- 玩家战队每季一条私有简报「{战队} 休赛期自主训练」（只列天梯变化 ≥ 400、战力变化 ≥ 1.5 或跨档的队员；下降表述为「新赛季天梯重新定级后回落」）。
  选手详情「潜力」一行只显示定性趋势（仍有成长空间 / 接近巅峰 / 已过巅峰，`developmentOutlook`，只读），不显示潜力数值。
- 实测（无头模拟，同种子对照关闭自主成长）：TI 时真实首发与当届真实水平平均相差约 −100~+700 天梯、+1~2 战力（关闭时 TI12 起 +1100~1500 / +6.5~8.5）；
  首发前十战力 88~91（关闭时 93~94）；TI1 起首发 SS+ 占比 TI1–TI8 为 27%~39%（关闭时 TI6 即约 69%）；Ceb（TI2 以 A 级登场）TI8 时 SS（11.4k / 85）。
  只有自主成长时，后期（TI10 起）首发 SS+ 占比仍会升到 50%~60%、首发 SSR 由 2~3 人升到 13~18 人：几乎全部来自选秀按用户指定分布生成（SS 5% / SSR 3%）、
  长期在役的 SS / SSR 程序生成新秀（TI1 起第 13~16 个赛季首发 SSR 中 13~14 人为「以 SSR 等级被选中的新秀」，真实选手 1~2 人），由下面的天梯相对校准处理。
- **天梯相对校准**（第九波 QA，`development.calibrateLadder`，参数 `CONFIG.development.ladder`）：天梯是相对排名——每个赛季自主成长之后（新秀选秀之前）按
  「赛季内预期成长之后」的天梯（≈ 本届 TI 时的水平）统计联赛在籍选手（未解散战队的正式队员）：SSR > max(3, 在籍人数 × 3%) 或 SS 及以上 > 在籍人数 × 36% 时，
  **没有当届真实参照**的选手（程序生成选手、真实选手最后一届数据之后）按预期天梯从低到高回落，使其本届 TI 时约在该等级门槛 − 150（潜力上限同步下调）；
  人类玩家战队中训练投入 ≥ 800 天梯的选手（经理花钱练出来的）排在最后才回落，但仍计入名额（联赛整体公平，成长重平衡 2026-10-09；被卖到 AI 战队后不再优先保护）；
  有当届真实轨迹的真实选手不参与（真实历史优先）。确定性，不消耗随机数；回落计入玩家战队的自主训练简报（「新赛季天梯重新定级后回落」）。
  新秀等级分布（用户指定）不变：选秀在校准之后，选中的新秀至少以原等级打完首个赛季。
  参照真实阵容（rosters/ti1–15）：在籍 SS+ 14%~55%（均值约 30%）、首发 SS+ 21%~73%（TI 参赛队，TI12–15 约 41%~53%）、SSR 每届 1~3 人。
- 校准后实测（无头模拟，TI 正赛回合统计，每组 3 局）：
  | 起点 | 首发 SS+ 占比（第 1 季 → 第 5 季 → 末季） | 首发 SSR 人数 | 在籍 SS+ / SSR |
  |---|---|---|---|
  | TI1 起 16 季（接管 EHOME） | 27% → 33% → 46%（TI10–16 稳定在 44%~49%；校准前 54%~60%） | 2 → 5 → 8（TI10–16 为 5~8；校准前 11~18） | 末季 38% / 8（校准前 49% / 18） |
  | TI5 起 12 季（接管 EG） | 27% → 38% → 44%（TI10–16 为 44%~49%） | 2 → 6 → 6（5~7） | 末季 35% / 6 |
  | TI9 起 8 季（接管 OG） | 40% → 46% → 45% | 3 → 6 → 8 | 末季 37% / 8 |
  真实首发与当届真实水平仍平均相差 −100~+650 天梯、0~2.5 战力；首发前十战力 89~93。vitest「TI9 → TI16」集成用例的边界相应收紧（首发 SS+ < 52%、全体 SSR < 4%）。

### 2.5 教练
- 属性：`age`、`tier`（天梯等级）、`insight`，派生 `talentBoost`、`resilienceBoost`（不同教练幅度不同，按等级 + 随机 ± 浮动），工资。
- 教练市场容量：每赛季初自由教练年龄 ≥ `CONFIG.coach.retireAge` 退出；仍多于 `freePoolMax`（40）时按等级、灵性保留最好的（有东家的、玩家旧部转任的不受影响）。
- **赛季教练供给**（第九波，`coaches.ts`，参数 `CONFIG.coachSupply`）：赛季初在新秀选秀之后、休赛期转会潮 / AI 季前转会之前（容量清理之后）全局执行一次：
  该届 roster 中尚未进入游戏的真实教练（战队主教练 + 自由教练，`src/data/coachIndex.json` 由 `scripts/build-coach-index.ts` 生成；本世界仍在役 / 未出道的同名选手、已转任者、超龄者除外，每季最多 12 名）+ 程序生成 6 名（C 20 / B 30 / A 26 / S 15 / SS 7 / SSR 2）+ 上赛季退役选手转任；
  不足时追加生成，保证可签约教练 ≥ max(8, 没有主教练的战队数 + 5)、其中 S 级及以上 ≥ 3。首次出现的教练记 `arrivedTi`，教练页标记「新到」并可按等级 / S+ / 新到筛选；新闻「【教练市场】本赛季新增 N 名教练」（公开）。
  使用按 (存档 id, 赛季) 派生的子随机流，不消耗主随机序列。AI 只在没有主教练时按 `CONFIG.ai.coachHireChance` / 预算聘请，按「与本队首发平均等级的差距」加权随机挑选，且签下后市场不得跌破上述下限（`aiCoachCandidates`）。
  实测（无头模拟 TI9 起 4 季 × 30 局）：AI 季前签约之后赛季初平均可签约约 35 名（S+ 约 17 名），最少 9 名，保底从未被打破。
  第九波 QA 复测（第 1 回合统计，TI1 / 5 / 9 / 10 / 13 / 15 起多组共 160 余局）：新游戏第一个赛季（不执行供给，只有开局数据中的自由教练）平均可签约 10~17 名、S+ 3~6 名、空缺 2~12 个，
  单局最少 8 名；第二个赛季起 16~65 名（TI1 起的前两三个赛季 S+ 只有保底的 3 名左右，TI6 起 11~55 名），每个赛季都有教练可签。市场里 S+ 占比后期偏高（约 3/4）：容量上限按等级保留最好的 40 名、退役选手按原等级转任，
  高等级教练逐季沉淀；工资与签约费按等级递增（SSR 教练每回合 6800 × 经济指数，签约费 4 倍工资），小俱乐部仍需取舍。
- **教练不随年龄变化**。教练岗位可空缺。
- 作用：每次训练使队员 `talent += talentBoost×k1`、`resilience += resilienceBoost×k2`；BP 时教练灵性按权重计入战队灵性。

### 2.6 归属感
- 降低：欠薪、长期替补（阵容超出常规上限时更快，见 3.1）、连败、俱乐部荣誉显著低于选手身价、薪资低于预期（2.6.1）、丑闻、拒绝想走选手的报价。
- 提高：夺冠、胜利、加薪、续约、谈心（免费，每人每回合一次，按成功率）、团建（花钱，全队）、薪水高于预期、效力于远超期待的豪门。
- `loyalty < config.loyalty.leaveThreshold`（默认 30）时，每回合有概率「主动申请离队」（加薪挽留 / 尝试挽留 / 放行）或被 AI 战队挖走（AI 支付违约金，可能低于身价）。
- 球员管理（第四波，`squadOps.ts`）：加薪 10/20/30%（每人每赛季一次）、谈心、团建；挂牌转会（挂牌期一整个赛季，整个挂牌期无人出价才自动解约且无补偿；见 3.4）。

#### 2.6.1 隐藏的预期薪资与归属感多维模型（第八波，`salary.ts`，数值见 `CONFIG.salary`）
- **预期薪资**（隐藏，界面不显示数值）：`expectedSalary = computeSalary(当前市场工资) × 荣誉系数 × 明星系数`。
  荣誉系数 = `honorBase + honorK × (所在战队荣誉/honorRef)^honorExp`（凸函数，荣誉越高增长越快，夹在 [honorBase, honorMaxFactor]）：
  100 荣誉（新俱乐部）≈ ×0.90、1000 ≈ ×1.06、1500 ≈ ×1.23、2000 ≈ ×1.46、2500 ≈ ×1.73、上限 ×1.9。小俱乐部的选手按略低于市场的工资就满意；豪门的明星要价远高于市场。
  明星系数 = 等级系数（A 1.02 … SSR 1.1）× (1 + min(50%, 近期热度 × 0.045))；热度 = 冠军 +1、TI 冠军再 +5、单局 MVP +0.05，每赛季 × 0.6（记录在 `player.salaryTrack`）。
  新秀合同期内（被本队选秀选中起到该合同到期，续约即结束；被别队选中后转投本队的不算）不计薪资差。
- **薪资差** `g = (预期 − 实际) / 预期`；界面只给定性满意度：`g ≥ mood.strongGap` 强烈不满、`≥ mildGap` 略有不满、否则满意（阵容页小图标、选手详情「薪资满意度 / 整体情绪」）。
- **每回合归属感（人类玩家战队）** = (荣誉维度 + 薪资维度 + 差距拉大惩罚) × 在队时长速度倍数：
  - 荣誉维度：战队荣誉 < 等级期待 × `loyalty.honorGapRatio` 时扣分（落差越大越多），远超期待时小幅加分；
  - 薪资维度：`g` 超过宽限后随 `g` 加速扣分，薪水高于预期小幅加分；`g` 比上回合拉大时额外扣分；
  - 在队时长速度倍数：加盟赛季 ×0.5、第二个赛季 ×1、第三个 ×2，之后等比（×4…，上限 `tenure.cap`，默认 4：×8 会让第 5 个赛季起的任何落差每回合扣 5 点以上，谈心也无法弥补）。
  - 「差距拉大」单回合最多 −`growthMax`（1.5，乘速度倍数前）：早期年代经济指数逐季上涨（最多 +50%）、天梯跨档都会让 g 跳变，避免一次跳变扣掉 20 点归属感。
  - 替补、胜负、冠军、谈心、团建、加薪、续约等原有因素不变。AI 战队用简化版（只保留固定的荣誉落差扣分）。
- **外部反应**：进入强烈不满时发布公开新闻「XX 对薪资不满」（冷却后可再提）；AI 报价概率 × (1 + k × 阵中最大 g)、目标权重 × (1 + k' × g)；
  低归属感时离队申请 / 挖角概率随 `g` 提高；归属感 < 85 但薪资强烈不满的明星（≥ S 级）也会被挖角（同一选手有冷却）；离队申请被挽留后有短暂冷静期。
- **开局与签约工资**（第八波平衡）：单机接管真实俱乐部时，正式队员工资对齐到预期 × U(0.86, 1)（`alignInitialSalaries`，只上调；数据工资是普通市场工资，不对齐的话接管高荣誉豪门的第一回合全队就强烈不满）。
  人类玩家战队签约自由选手 / 求购选手的工资 = max(市场工资, 预期 × (1 + 要价溢价 + 隐藏浮动))（`signingSalary`，转会市场与报价弹窗显示的就是实际工资）：豪门买人要按自己的地位开价，小俱乐部按市场工资。
- **续约**：选手要价 `renewalAsk ≥ 预期薪资`（预期 × (小幅溢价 + 按存档/选手/赛季固定的隐藏浮动)，归属感低时更高；界面显示的要价无法反推出精确的预期）；`renewContract(id, 赛季, 报价?)` 报价低于预期 → 拒绝（提示低于心理预期，不透露数值）。
  合同到期决策在赛季结算时生成、新赛季回合 0 处理：回合开始时按当前行情刷新要价（`market.refreshContractDecisions`），显示的要价即实际续约工资；等待续约决定的选手不上「对薪资不满」新闻。拒绝针对薪资强烈不满者的挖角报价同样会降低其归属感。
  **加薪**缩小差距，预览给出加薪前后的满意度；对薪资越不满，加薪的归属感收益越高。

## 3. 战队运营

### 3.1 阵容
- 5 个首发位置（C/M/O/SS/HS），其余为替补，首发与替补由经理安排（`setLineupSlot` / 自动排阵）。
- **阵容人数（用户反馈，2026-10-09：「阵容空位后不能签约也很奇怪」）**：`config.team.maxRoster`（8）是人类玩家战队的**常规上限（软上限）**，
  签约自由选手、求购选手、选秀、临时替补都可以超过它，**阵容人数从不产生推进阻塞**（`getAdvanceBlockers` 不再有「超编」）。
  超出的代价：每名签约选手的工资照付；长期替补（连续替补超过 `loyalty.benchGraceRounds` 回合）每回合除 `loyalty.benchPerRound` 外，
  每超出常规上限 1 人再 `loyalty.overRosterBenchPerRound`（−0.4，最多按 `overRosterBenchMaxExcess` = 4 人计：8 人阵容的替补每回合 −0.8，10 人 −1.6，12 人起 −2.4；
  `growth.overRosterBenchPenalty`）。界面只给温和提示「阵容 10/8：超出常规上限，替补归属感下降更快、工资照付」（总览待处理的提醒项、底栏右侧、转会 / 阵容 / 选秀页；
  `team.rosterOverflowNotice`），签约 / 报价前提示「签下后阵容 9/8……」（`team.rosterSigningNote`）。
- **绝对上限** `config.team.hardMaxRoster`（12）：只限制人类玩家**签约自由选手 / 求购选手**（`team.rosterSigningBlock`：「阵容已达绝对上限（12 人），请先解约或出售选手」）；
  赛事临时替补与选秀新秀不受限制（临时替补只限同时在队 `market.tempSubMax` = 5 人）。不需要先放弃现有队员才能签新人。
- AI 战队另按 `config.ai.maxRoster`（7）管理阵容（均进入自由市场）：选秀后超出时按「保留价值」（`rookieDraft.aiKeepValue`，见 3.3）放走最低的非首发；
  休赛期转会潮、AI 转会窗口（季前 / 中期）与 `aiEnsureRosters` 沿用原有逻辑，超出时放走评分最低的替补（因此 AI 选中的低评分新秀仍可能在同一个休赛期被放走，
  选秀板会标出「已离队 / → 新东家」）。
- 多人模式每个座位同样适用（按各自战队计算，无新增座位状态）。
- **AI 首发优先级**（用户决策 2026-10-10「首发优先使命选手和巅峰选手，然后再基于评分安排」；`lineupPriority.ts` + `team.autoLineup`，开关 `CONFIG.team.aiLineupPriority`）：
  AI 战队自动排阵时，先把**使命选手**（本俱乐部现实巅峰阵容的在队成员，与 `missions.missionOf` 同口径，使命完成后仍优先，7.3）排在各自的本位置，
  其次是**巅峰选手**（历届巅峰阵容 `synergies.json` 的冠军 / 标志性阵容成员，该届真实 TI 已打完才算，与羁绊觉醒同口径——开局不会因为「未来的冠军」让低评分新人首发）；
  同一位置有多名优先选手时先比优先级、再比综合评分，落选者回到候选中按评分竞争其余位置；其余位置照旧按评分做全排列搜索。有可出场的选手就不留空位，
  赛事可出场规则（签证 / 伤病 / 其他赛事的临时替补）照常适用。**人类玩家战队（含多人）的自动排阵不变**：首发由经理决定，自动排阵只按评分（玩家的「自动排阵」按钮与赛前自动补位都是求最强阵容，加入优先级只会让它变弱）。
  **AI 转会配套**（审阅修正，`lineupPriority.lineupPriorityLocks`，开关 `CONFIG.team.aiLineupPriority.lockTransfers`）：优先选手打本位置时该位置被「锁定」，
  AI 的按评分补强 / 换人（`ai.tryUpgrade` 取未锁定首发中最弱的一个、转会潮的补强 / 主动换人 / 明星去向、转会潮对玩家选手的求购）都跳过这个位置——
  否则买来的同位置选手会被 autoLineup 排到替补席，白花转会费与工资（首版未配套时，每届 TI 时全联盟约 4–8 名本赛季引进的 AI 选手坐在更早加盟的使命选手身后，
  合计工资约 1.2–3.8 万 / 回合；配套后 0.6–1.5 名，且几乎都是本赛季新到的使命选手顶掉了同位置的普通选手，属预期）。候选人自身优先级更高（如使命成员顶替巅峰选手）、
  或同级且综合评分更高时不算锁定；使命成员的引进（`missions.ts` / 转会潮 `pursueMissions`）不受影响。
  每次只多几次 Map 查找，不影响模拟速度（autoLineup 约 4–5 µs / 次，开启优先级反而略快——待排位置更少）。实测见 3.6.1 末「2026-10-10 调整实测」：AI 使命选手的首发率 76%–87% → 96%–98%，
  AI 首发平均评分 −0.2%–1.2%（未配套转会时 −0.7%–1.5%），TI 冠军首发中有 3 名以上使命 / 巅峰选手的占比 49%–77% → 64%–83%。
- 参赛时首发不足 5 人 → 必须临时招募替补（野外替补）；否则该场系列赛**弃权判负**（对手记满胜局、无对局记录，`SeriesResult.forfeit`）。
  AI 战队同理（先用替补自动补位，仍凑不齐才判负）。玩家在回合开始时收到「首发不足 5 人」提醒，推进按钮与比赛入口也会给出弃权警告。

### 3.2 训练（休赛回合）
- **训练是队员成长的主要来源（看天赋、花钱多）**；比赛主要带来荣誉、金钱与韧性（见 2.3）。
- 每个休赛回合有 **1 次免费训练**（`trainingSessionsFree`），可选焦点。
- **额外训练**：花金币购买，价格 `extraBaseCost × extraCostGrowth^本回合已购 × min(1.6, 1 + 2% × 本赛季已购) × econIndex`
  （1 万 × 1.25^k：经济指数 1 时同一回合第 1/2/3 次约 1.0/1.25/1.56 万，下回合恢复；本赛季累计缓慢上涨，赛季初重置）。每回合额外训练上限 `config.training.maxExtraPerRound`（3）。
  训练赛 `(1.2 万 + max(0, 对手/本队 − 0.8) × 2 万) × econIndex`（约练同等实力 1.6 万、强得多的对手约 2.6 万）。
  成长重平衡前为「× 1.35^本赛季已购次数」，买几次就贵到买不起，「每个休赛回合都加练」不可能；现在可以狂练，但每个休赛回合都加满 3 次再约一场训练赛，
  一个赛季（约 15 个休赛回合）要花约 80~100 万（实测见下）——豪门一个赛季收入的一半左右，中游俱乐部收入的 2 倍上下，新俱乐部只有攒了钱才练得起：
  是要和签人 / 存钱取舍的大投入。复核（2026-10-09）：首版 2 万 × 1.2^k、训练赛 1.5 万 + 2.5 万 × 比值时整季狂练要 106~130 万（同期收入的 1.9~3.7 倍），
  自然资金下几乎没人买得起，狂练的成长 95% 来自不花钱的免费训练（只是放弃可选赛事），「花钱」名不副实。
- **天赋 / 韧性按回合成长**：额外训练、消耗已购次数的训练赛、回合末自动完成的已购次数，对天赋（年轻自然增长 + 教练）与韧性（教练）的提升 × `extraSessionAttrMult`（0.2），
  每回合第一次（免费）训练全额（见 2.3）。AI 加练同样折算。

### 3.3 新秀选秀（赛季初，第八波取代抽卡；`src/engine/rookieDraft.ts`，参数 `CONFIG.draft`）
- 每个赛季初（TI 结算的退役 / 年龄 / 合同之后，休赛期转会潮与赛程之前；新游戏第一个赛季同样举行）自动举行，所有战队（含玩家）参加；多人模式全局一次。
- 新秀池 = 本赛季登场的真实新秀（`futureRookies` 到期）+ 程序生成新秀（`generatedPerSeason`）。程序生成新秀等级 A 15% / S 10% / SS 5% / SSR 1%（其余 C/B）；
  SSR 伪随机分布 + 跨赛季保底：每 100 名新秀至少 1 名 SSR（真实新秀保留数据等级但计入保底计数，任何 SSR 出现即清零；`rookieDraft.ssrPity`）。
  实测（第八波 QA，约 4000 届选秀、20 万名新秀）：全部新秀（真实 + 生成）约每 100 人 1 名 SSR；只看程序生成新秀约 1.9%——真实新秀多的赛季（TI2 有 66 名真实新秀、只剩 4 个生成名额）
  保底计数主要由真实新秀填满，触发的保底 SSR 落在生成名额上；真实新秀少的年代（TI9、TI13 起）约 0.7%~1.0%。这是「真实新秀计入保底」规则的结构性结果。
  选秀分配：上赛季排名后三分之一的战队选中的新秀平均战力明显高于前三分之一（约 68 vs 60），抽签中签者平均排名在倒数几位。
- 顺位：上赛季最终排名最差的 14 支战队按 NBA 权重抽签决定首轮前 4 顺位，其余按排名倒序；第 2 轮起按排名倒序（默认 2 轮）。首个赛季按「实力排名 + 荣誉排名」。
- 各队自动选人：综合评分 + 天赋/年龄潜力 + 位置需求（首发空缺、强于现首发、同位置过多扣分），在前 3 名中按权重随机。
  **不再因阵容人数放弃顺位**（用户反馈，2026-10-09）：每支战队的每个顺位都选人（新秀池选空为止）。
  玩家战队保留全部选中的新秀，阵容可超出常规上限（见 3.1），首发与替补由经理决定——新秀只会自动填进**空着的**首发位，不会顶替已有首发；
  AI 战队选秀后若超出 `ai.maxRoster`，按「保留价值」（`rookieDraft.aiKeepValue` = 综合评分 + 天赋 × talentWeight + 年轻 × youthWeight）放走最低的非首发进入自由市场
  （被放走的本届新秀在选秀记录中标为 released）。
- 新秀合同首轮 3 赛季、之后 2 赛季；工资按新秀薪资表（按总顺位递减，× 经济指数）。落选新秀进入自由市场。
- 玩家可在赛季初免费放弃本届选中的新秀（`releaseDraftedRookie`，进入自由市场，无补偿、不扣荣誉；赛季初从阵容页 / 选手详情的普通解约入口放弃本届新秀同样免费，`releasePlayer` 会转给它）。被放弃后又签回的选手按普通合同处理。落选新秀在登场赛季内不会因自由市场人数上限被清退。结果：每位玩家一个弹窗 + 新闻（状元签、选秀大会、玩家战队的新秀）；「转会 › 新秀选秀」页展示抽签概率表、本届选秀板、我的新秀与往届选秀。

### 3.4 招募 / 转会 / 临时招募
- **招募**：签约自由选手，支付签字费 + 工资。选手意愿取决于俱乐部荣誉 vs 选手身价等级。玩家战队签约 / 求购的工资按本俱乐部地位开价（`salary.signingSalary`，见 2.6.1），AI 战队按市场工资。
- **转会**：向 AI 战队报价求购；AI 接受概率 = f(报价/身价, 选手在原队重要度, 选手归属感)；选手意愿受荣誉影响。AI 也会向玩家报价求购（对薪资不满的选手更常被盯上）。
- **挂牌**（第四波；2026-10-12 用户需求「队员挂牌到解约持续一整个赛季，而不是三个回合」改为整赛季）：玩家可挂牌出售选手（标价 = 身价 × 0.5~2.0），挂牌期内等待 AI 出价；
  整个挂牌期无人出价才自动解约（无补偿、不扣荣誉），收到过报价但未成交则挂牌结束、选手留队。`squadOps.ts`，参数 `CONFIG.squadOps`。
  - **挂牌期** = `listingSeasons`（1）× 每赛季倒计时回合数 = `calendar.regularRounds`（18）个转会回合（`listingDurationRounds`，挂牌时写入 `TransferListing.totalRounds` 固定）。
    倒计时在每个常规赛回合结束时走一格：转会窗口开放的回合是赛季初 + 18 个常规赛回合，但赛季初没有回合结算（`advanceRound` 从赛季初直接进入第 1 回合），
    TI 预选 / 正赛转会锁定期间暂停；挂牌跨越 TI 与休赛期（退役 / 合同 / 转会潮 / 选秀 / 赛季初）保留，因此在**下赛季的同一时间点**到期
    （第 r 回合挂牌 → 下赛季第 r−1 回合结束时到期；赛季初或第 1 回合挂牌 → 本赛季常规赛最后一回合结束时到期）。
    若按「窗口开放回合 = 常规赛回合 + 1 = 19」计，会比一个赛季多走一回合，所以不采用。
  - **出价**：下一回合仍开放转会窗口时才掷骰（常规赛最后一回合照常计时但不出价：报价会落在锁定期，无法接受），概率 = 曲线(标价/身价) × 等级系数 × 需求系数（见 `bidChanceCurve` 等，未改）；
    每个挂牌记录已经历的出价机会 `bidRolls`。前 `listingFreshRolls`（3）次与原 3 回合规则完全相同（不消耗额外随机数）。
    挂牌报价在回合结束时生成，从下一回合起有效 `market.offerExpireRounds`（2）个回合；第 17 回合结束时生成的报价只能在第 18 回合处理（之后转会锁定、`expireOffers` 作废），新闻注明「仅下一回合内有效，之后 TI 转会锁定、报价作废」（`offerUsableRounds`）。
  - **收到过报价**（`TransferListing.hadBids`，决定到期是解约还是留队）：在 `market.createTransferOffer` 创建报价时记录——挂牌报价、普通求购报价、挖角报价都算，
    包括当回合就被拒绝的报价、常规赛最后一回合被转会锁定作废的报价（`season.endRound` 里 `expireOffers` 先于挂牌结算）；挂牌前就已收到、仍待处理的报价在回合结算时补记。
    原来只在回合结算时看有无待处理报价，上述两种情况会被当成「从未收到报价」而自动解约（整赛季挂牌让第 18 回合计时后，前一种成了常见路径）。
  - **挂牌过久的报价意愿衰减**（防止「高标价挂一整季等人接盘」）：第 k 次（k ≥ 3，从 0 计）出价机会的概率 × (1 − 强度 × (1 − `listingStaleDecay`^(k − 2)))，
    强度 = (标价/当前身价 − 1.0) / (1.3 − 1.0) 夹紧到 [0, 1]（`listingStaleRatioRange`）：标价不高于当前身价时不衰减，≥ 1.3 倍时全额衰减（0.7、0.49、0.34…）。
    界面「报价概率」为含衰减的值，衰减时标注「挂牌较久」。
  - **提醒**：从未收到报价时，剩 `listingReminderRounds`（3）个回合与最后 1 个回合各一条新闻（最后一个计时回合不能出价时措辞改为「挂牌不会再收到新的报价，回合结束时转会窗口锁定……如想留下他，请撤销挂牌」）；收到过报价则不提醒（不会解约）。
    提醒是挂牌方的私有消息（`visibility: 'private'`、`actorTeamId` = 挂牌方，`multi.seatView` 对其他座位过滤），多人模式下对手看不到「无人报价」与经营建议；挂牌 / 挂牌报价 / 挂牌到期 / 挂牌结束等转会新闻仍公开。
  - **合同到期**：挂牌期跨越 TI 结算，挂牌中的选手合同到期时，续约决策正文注明挂牌状态（标价、剩余回合；放他离开 = 合同到期自由离队、无需补偿，挂牌随之结束；续约则挂牌继续；每回合开始按当前挂牌状态刷新）。
    懒人「下一回合」对合同到期默认续约 1 赛季（`DEFAULT_DECISION_CHOICE.contract = renew_1`），挂牌中的选手也一样（续约要价通常高于原工资）；是否对挂牌中的选手改为默认放走见 ROADMAP「待用户决定」。
  - **清理**：选手转出 / 解约 / 自由离队（`market.clearDepartureState`）、退役（`growth.processRetirements`）、禁赛、离开人类战队、战队解散时挂牌失效；游戏结束后不再有有效挂牌（`activeListing`）。
  - **旧存档**：缺 `TransferListing.v` 的挂牌按原 3 回合规则已过的回合迁移：剩余 = 18 − (3 − 旧剩余)，`bidRolls` = 已过回合（`migrateListing`，幂等、确定性、不消耗随机数）；
    读档时（`save.importSave`）全部迁移，多人房间的存档不经读档，在各座位的回合结算中迁移；迁移前界面用 `listingProgress` 显示换算后的进度。

### 3.5 荣誉
- 新俱乐部初始 100；真实俱乐部按历史成就初始化（数据文件中给出）。
- **荣誉 < 0 → 战队解散，游戏提前结束。**
- 荣誉只能通过比赛积累（及事件/转会扣减）。
- 赛事荣誉结算（每项赛事结束时）：
```
p(rank, n) = (rank-1)/(n-1)    // 名次百分位，0=冠军，1=垫底；并列名次取区间中点
Δ = tierBase[tier] × ( wExp × (pExp - pAct)              // 对比赛前预期（不达预期扣分）
                     + wYoY × (pSameLastSeason - pAct)   // 同比：同系列赛事上赛季名次
                     + wMoM × (pPrevEvent - pAct)        // 环比：上一项参加的赛事名次
                     + placeBonus(rank) )                // 冠军/亚军/四强奖励
     + beefBonus                                          // 宿敌加成（逐场结算）
```
- 赛前预期 `pExp`：按参赛队伍「战力 + 荣誉」排名得出，赛前在赛事页公示「赛前预期：第 X 名左右」。
- **参照校准（第六波）**：名次受随机性影响会向中游回归（实测预期第 1 的队伍平均名次百分位约 0.25）。热门半区（参照百分位 < 0.5）的
  预期 / 同比 / 环比参照按 `0.5 + shrink × (p - 0.5)` 收缩（`CONFIG.honor.expectationShrink / historyShrink`），冷门半区不变；
  预期项再做一次零和平移（`expectationZeroSum`），整体不额外抬高联盟荣誉。效果：强队拿到亚军/季军不再扣分，荣誉不会逐季下滑。
- **低荣誉减损**：单项赛事扣分 × lerp(0.4, 1, 荣誉/300)（`lowHonorLossRef / lowHonorLossMinMult`），加分不受影响；
  解散仍可能发生（欠薪、丑闻、假赛、长期失利），但不会因几项赛事失常而突然解散。
- 荣誉影响：转会、招募、临时招募获得高天梯等级的概率；赞助类事件金额；赛事邀请。

## 4. 赛事

### 4.1 赛程生成（赛季初）
- 来源：`src/data/tournaments/season{ti}.json`（真实赛事：名称、等级、日期、地点、奖金、队伍数、赛制）。未来赛季（无数据）复制最后一个有数据赛季的模板并推演名称/日期。
- 赛事等级 `tier`：`TI` > `major` > `premier` > `minor` > `qualifier`。
- 每项赛事对玩家的状态（`PlayerEntryStatus`）：
  - `invited` 受邀（上赛季排名 TOP N 或荣誉足够高 → 自动报名、直接进入正赛）。**邀请不再强制**：开赛前可婉拒（`unregisterFromTournament`），无荣誉惩罚，新闻「【婉拒邀请】…」，空出的正赛席位在开赛时由 AI 战队递补
  - `declined` 已婉拒（主动婉拒，或赛季初同回合多项邀请冲突时自动婉拒：只保留等级最高者为 `invited`，其余为 `declined`）。开赛前可重新接受（`registerForTournament`：在受邀名单中 → 回到 `invited`，否则按普通报名 → `registered`），但受「每回合最多一项」约束：同回合已受邀/已报名其他赛事时失败，需先婉拒/取消那一项
  - `registered` 已报名（未受邀，开赛时需先打封闭预选赛阶段）
  - `open` 可报名（满足最低荣誉；未受邀者需先打封闭预选赛阶段）
  - `locked` 荣誉不足 / 赛区不符，不可报名
  - **例外**：TI 正赛与 TI 赛区预选赛是赛季收官，按积分榜自动安排，**必须参加**，不可婉拒或退出
- 玩家确认报名后，赛季回合表固定：「本赛季共 X 个大回合（Y 个赛事回合，Z 个休赛回合）」。报名与婉拒/重新接受均可在赛事所在回合开始前修改（回合开始即开赛，之后锁定）；已婉拒的赛事不计入赛事回合。

### 4.2 赛制
- 阶段（stage）：`qualifier`（单败，仅未受邀队伍）→ `groups`（小组循环 Bo1/Bo2）→ `playoffs`（双败或单败，决赛 Bo3/Bo5）。
- 名次：小组赛淘汰按组内排名划分区间；淘汰赛按被淘汰轮次划分区间（如 5–6 名）。
- 奖金按名次比例分配（`config.tournament.prizeShare`，发放额经奖金压缩，见 3.6），另有积分（巡回赛积分 `circuitPoints`）。
- **线上公开赛**（补位赛事）：常规回合无赛可打时自动补一项开放报名的线上赛（不计巡回赛积分，奖金低于典型 Minor）。

### 4.3 TI 资格
- 赛季巡回赛积分前 `directInvites` 名直邀 TI。
- 其余队伍在 `ti_qualifier` 回合打所属赛区预选赛，各赛区名额见 `tis.json`。
- 下赛季赛事邀请依据：上赛季最终排名（积分 + TI 名次）。

### 4.4 单场比赛
1. **BP**（队长模式简化版：禁 4 → 选 4 → 禁 4 → 选 4 → 禁 2 → 选 2，ABBA 交替）。可选自动/手动；手动时每个己方回合给出推荐英雄（推荐质量受灵性影响）并可搜索任意可用英雄。英雄池随日期（英雄发布日期）和版本强度（meta）变化。
2. **大老师胜率**：`dotaPlusWR = clamp(0.5 + draftDiff×kDraft + insightDiff×kInsight, 0.15, 0.85)`。
3. **最终胜率**：`pWin = wDraft × dotaPlusWR + wStr × strengthShare`，`strengthShare = rA^γ/(rA^γ+rB^γ)`，`r` 为五名首发 `playerRating` 之和 + 教练加成。
4. **局内突发事件**：每局 0–2 个（掉线、心态爆炸、神级操作…），临时修正选手战力（受韧性缩放），影响该局 `strengthShare`。
5. 按 `pWin` 随机决定胜负，再生成与结果一致的**文字直播时间线**（一血、对线、团战、肉山、推塔、买活、高地、GG），包含比分、经济差。
   - **时长 / 击杀按年代标定**（用户反馈 2026-10-10「下调 KDA 模拟数值，尽量接近真实」；数据：OpenDota 历届 TI 联赛全部对局，2012–2026；`CONFIG.match.eraByTi` / `match.eraMatchBaseline`）：
     每个赛季取该届 TI 的真实平均时长 / 平均总击杀（如 TI3 35.9 分钟 / 35.9 杀、TI8 39.5 / 54.1、TI13 37.9 / 40.7、TI15 46.8 / 52.0；TI1 无数据沿用 TI2，TI16 取 TI12–15 均值）。
     时长 = 年代均值 × e^(阵容偏后期 + 势均力敌 + 爆冷 + N)（对数正态，p10 ≈ 0.66×、p90 ≈ 1.4×）；总击杀 = 年代均值 × (时长 / 年代均值)^0.76 × 噪声（长局击杀多、每分钟击杀少）；
     胜方击杀占比随时长衰减（真实：22 分钟 0.78、40 分钟 0.65、60 分钟 0.57；碾压局短且一边倒，约 6% 的对局胜方击杀更少）。时长 / 击杀的随机数用量与改动前相同（快速模拟的主随机序列逐次对齐，胜负等后续结果不变）。
     实际赛季流程实测（每届约 1500~2200 局）各届平均总击杀 / 时长与真实值相差 ≤ 2%；场均 K/D/A 按位置（1~5 号位）TI9 赛季 6.9/6.7/4.6/3.2/2.2 击杀、3.2~6.2 阵亡、8.8~12.5 助攻（真实 TI9 7.4/6.9/4.2/3.3/2.1、3.2~6.5、8.9~13.4），KDA 约 3.3（真实 3.0~3.6）。
     QA 复核（2026-10-10，`simulate.ts --dump` 后按 `PediaState` 聚合统计，TI3 / TI9 / TI13 起各一个赛季、约 1900~2100 局）：场均总击杀 35.9 / 47.0 / 40.3、时长 36.0 / 39.9 / 37.8 分钟；
     各位置 KDA 在三个年代都稳定在 1 号位约 4.9、2 号位 4.1、3 号位 3.4、4 号位 2.8、5 号位 2.35（击杀 / 阵亡 / 助攻的绝对值随年代总击杀等比缩放）。
6. 赛事结束后，参赛选手按名次获得成长，使用 2.3 的天赋随机公式：主要是**韧性**（名次越好、打得越久、赛事越大越多，TI 最多），战力 / 天梯 / 灵性只有少量（约为改动前的 30%）。

## 5. Dota2 版本更新
- `src/data/patches.json`：真实版本号、日期、标题、更新方向摘要、各位置战斗力倍数 `powerMult` 与灵性倍数 `insightMult`（如「地图增加边路传送门：O 0.98，SS 1.03」）。

- 每个版本重新生成英雄强度表（meta），种子 = 版本号，并结合补丁数据中的 `heroBuffs/heroNerfs`。
- 超出真实数据的未来日期 → 程序化生成版本（7.41、7.42…），倍数在 [0.97, 1.03]。

## 6. 随机事件（`events.ts` + `funEvents.ts`）
**所有事件在每个回合开始时都可能发生**（包括赛季初回合 0、休赛回合、赛事回合、TI 预选与 TI 回合），按概率滚动，事件可带**选项**（进入消息中心，未处理前不能推进回合）。

**玩家战队负面事件降频**（第九波，用户决策；`events.ts` / `scandal.ts`，参数 `CONFIG.humanEvents`）：只作用于人类战队（单机玩家 + 多人模式每个座位），AI 战队与正面事件不变，无厘头事件（用户设定）不受影响。
- 负面事件（情感受挫、伤病、丑闻、战队 beef、假赛风波、签证问题）概率 = 基础 × 难度倍数 × `negativeMult`（0.7）；TI 预选与 TI 正赛回合再 × `tiNegativeMult`（0.25），合计 × 0.175。
- **TI 预选 / TI 正赛回合禁赛类结果恰为 0（硬规则，无开关）**：不触发假赛风波（照常掷骰以保持随机序列）；冷处理后到期的「假赛调查结果公开」顺延到 TI 之后（下赛季首个回合）；俱乐部全员假赛只在常规赛回合计划与曝光。人类俱乐部全员假赛概率仍为用户确认的 0.1% / 赛季（`clubBanMult` = 1）。
- **签证被拒同属「缺阵类」结果**（第九波 QA，按用户原话「禁赛等结果的事件降到 0」）：TI 预选 / TI 正赛回合的签证检查概率为 0（照常掷骰），明星不会因签证错过 TI；常规赛回合照旧（× 难度 × 0.7）。
  TI 期间仍可能出现的只有情感受挫 / 伤病（临时降低战力，× 0.175）与战队 beef（只影响荣誉）；欠薪导致的离队属经营结果，不在此列。界面「玩法说明 · 随机事件」同步说明。
- 实测（无头自动经营模拟，TI9 起 4 季 × 30 局，`negativeMult = tiNegativeMult = 1` → 默认值）：接管 OG 每赛季 5.5 → 3.6 起、其中 TI 两回合 0.50 → 0.14 起；新俱乐部每赛季 3.8 → 2.4 起、TI 两回合 0.44 → 0.09 起；TI 回合禁赛 0。
- 第九波 QA 复测（4 季 × 40 局 / 组，含 TI 签证为 0）：每赛季负面事件 接管 OG 4.7（降频前）→ 3.0、接管 EG（TI5 起，北美赛事多）5.7 → 3.9、接管 Liquid 2.7、新俱乐部 3.2，
  其中情感受挫约 1.2~1.4、伤病约 0.8~0.9、签证约 0.2~1.1、beef 约 0.4、丑闻约 0.15、假赛风波约 0.03；TI 两回合合计 0.39~0.49（降频前）→ 0.05~0.11 起，TI 回合禁赛与拒签均为 0（本次修改前 EG 的 TI 回合仍有约 0.05 次 / 赛季拒签）。

### 6.1 无厘头搞笑事件（`funEvents.ts`）
声明式事件表（`FUN_EVENTS`），**梗由用户设定**，开发侧不自行添加内容。每回合以 `CONFIG.events.funEventChancePerRound` 概率从满足条件的事件中按权重抽一个触发；支持效果：金币、荣誉、全队/单人战斗力（临时或永久）、归属感、灵性、韧性、天梯；支持带选项事件；`requirePlayerId` 限定某选手在队时触发。
- 当前内容：**猪哥（Chalice）牙脱落事件**——Chalice 在玩家战队时可触发，选手集体补牙，资金 −10000。

| 事件 | 触发 | 效果 |
|---|---|---|
| 假赛风波 | 极低概率，低归属感/低工资选手更高；真实选手、联盟明星大幅降低；同队 2 个赛季内不重复；AI 战队概率单独设置（更低） | 选手永久禁赛（移出阵容），荣誉大幅下降（扣分不超过当前荣誉的一定比例，小俱乐部不会因此直接解散）；选项：配合调查（扣分少）/ 冷处理（风险） |
| 俱乐部全员假赛（`scandal.ts`） | 每支战队每赛季掷一次 `CONFIG.scandal.clubBanChancePerSeason`（0.1%，确定性子随机流，不消耗主随机序列），命中则在本赛季随机一个常规赛回合开始时曝光 | 俱乐部除名（`team.banned` + `disbanded`），全部正式队员永久禁赛，公开重磅新闻；AI 俱乐部由新组织补位（接替未开赛赛事的邀请）；单机玩家俱乐部 → `gameOver.reason = 'banned'`；多人座位出局转观战 |
| 情感受挫 | 每人每回合小概率 | 战力 ×(1−x) 持续 N 回合（受韧性缩放） |
| 签证问题 | 下一项参加的赛事在北美（美区）时高频；CN/SEA/SA/CIS 选手更易 | 该选手无法参加该赛事 → 需临时招募野外替补或用替补 |
| 丑闻事件 | 小概率 | 荣誉下降，相关选手归属感/状态下降 |
| 战队 beef | 小概率，随机一支对手战队 | 本赛季与该队交手胜利/失败时额外 ± 荣誉 |
| 俱乐部欠薪 | 资金不足支付工资 | 荣誉下降、全员归属感下降、归属感低者可能主动离队 |
| 其他（正/负） | 状态火热、赞助商注资、直播合约、伤病、粉丝见面会等 | 金币/荣誉/临时属性 |

## 7. AI 战队
- 每个休赛回合自动训练 1 次（随机焦点），富队 / 普通队另有少量额外训练，本赛季参赛比例高的战队休赛回合加练（`aiBusyExtraPerRound`）；收益 × `aiGainMult`
  （战力 / 灵性与玩家相同，天梯 ×0.92，见 2.3 / 3.2）；加练的天赋 / 韧性收益与玩家的额外训练一样 × `extraSessionAttrMult`。AI 加练不花钱。
- 转会窗口内：补齐阵容、替换弱位、签约自由选手；挖角低归属感选手（含玩家选手，会发出报价）。新秀只通过赛季初选秀获得（第八波起不再在休赛期提前签下真实新秀）。
- 自动报名赛事（按排名/荣誉/赛区），赛事结果后台模拟。
- 同样经历年龄增长、退役、版本更新与随机事件（简化版）；归属感用简化版（只有固定的荣誉落差扣分，不计薪资预期）；工资按市场工资。

### 7.1 休赛期转会潮（第五波，`shuffle.ts`，参数 `CONFIG.shuffle`）
每届 TI 结算后（退役 / 年龄 / 合同之后、选秀之后）、新赛季赛程之前执行一次（新游戏第一个赛季保留真实初始阵容，不触发）：
- 满意度：上赛季各赛事「预期名次 − 实际名次」、赛季最终排名 vs 战力排名、TI 成绩；不满意的队换 1~3 名首发，争冠队 / 卫冕冠军 0~1 名，长期核心与高归属感选手更难被换。
- 选手意愿：弱队 / 不满意队里的明星求变、强队明星寻求新挑战（顶级战队之间横向流动）、低归属感选手求去、强队老将下放、欠薪队甩卖。
- 市场多轮连锁：明星先由符合条件的强队争夺，之后自由选手（含选秀落选新秀）/ 挂牌 / 挖角；罕见情况下资金或荣誉见底的 AI 战队解散，新组织接手部分核心（每届至多 1 支）。
- 玩家战队只会收到更频繁的报价与离队申请，不会被直接搬走选手。新闻：【传闻】→ 每笔知名转会 →【转会窗口】汇总。
- 第十波 #3：使命俱乐部在明星去向之前优先引进缺失的使命成员，使命成员更难被换下 / 挂牌 / 挖走 / 裁掉（见 7.3）；解散后接盘的新组织记 `Team.founded`（kind fictional）。

### 7.2 新俱乐部涌现（第十波 #2，`clubs.ts`，参数 `CONFIG.clubs`，数据 `src/data/clubIndex.json`）
- **数据**：`scripts/build-club-index.ts` 由全部 `rosters/ti*.json` + `legacyClubs.json` + `branding.json` 生成，以**组织**为单位：改名 / 冠名的战队并入同一组织（PSG.LGD = LGD、G2.iG = Invictus Gaming、TNC Predator、BOOM、Nigma Galaxy = Team Nigma、MOUZ、Thunder Awaken、Soniqs、TSM、Iron Wing、TEAM VISION = PARIVISION，与品牌变迁 7.4 一致，避免重复建队），
  二队（LGD.Forever Young、VG.Reborn、iG.Vitality）与合作冠名的其他组织（PSG.Quest）独立；每届出现的品牌 / 荣誉 / 资金 / 队员（含位置）/ 主教练、首次出现届次、现实巅峰阵容（7.3）与最好的 TI 名次。
  roster / legacyClubs / branding 任一变动后需重新生成（`tests/clubs.test.ts` 校验与源数据一致）。引擎静态导入（约 120 KB，gzip 后并入 data 块）。
- **时机**：每个赛季初（赛季自主成长之后、新秀选秀与休赛期转会潮之前）全局执行一次；新游戏第一个赛季不执行（开局届的 roster 已包含该届全部俱乐部）；`state.clubFounding.ti` 防重复。随机数取 `rngOf(state)`。
- **候选**：当届 roster 中出现、而本局从未有过该组织战队（含已解散 / 除名）的真实组织——现实中后来才成立的俱乐部在其**首次出现**的赛季成立（Secret TI5、OG / Wings TI6、Spirit TI9、Tundra TI10、Falcons TI13……）；
  开局届名单里恰好缺席、之后重新出现的组织在重新出现的赛季加入；本局中解散过的组织不再重建。按重要程度排序：现实 TI 冠军次数 × 3000 + 最好名次（前四 1500 / 前八 800 / 前十六 200）+ 当届 TI 正赛队 1000 + 荣誉 / 10
  （历史地位优先：Spirit 以 TI9 DNQ 身份首次出现，仍先于当届一次性参赛的队伍成立），每季至多 `maxRealPerSeason`（3）家。
- **成立**：当届名称 / 简称 / 赛区 / 配色与荣誉（roster 评级）；资金 = `economy.realClubStartingFunds`（与开局 AI 战队同一公式：数据资金 × 0.2 封顶于强队锚定额 × 年代系数，3.6），不低于签约后每回合工资 × 12；「上赛季排名」插入排名表的 60% 处、其后顺延（选秀顺位 / 邀请 / 赞助，不白拿状元签概率）；主教练用当届数据（市场中自由、或尚未进入本局的真实教练）。
- **签回当届真实选手**：自由身直接签；AI 战队的选手由创始投资支付转会费（身价 × U(1.0, 1.3)，俱乐部运营资金不变、卖家照收）求购，卖家放人概率 0.75 − 头号选手 0.25 − 卖家自己的使命成员 0.45；
  **人类玩家战队的选手一律不动**（成立新闻注明「目前效力于玩家战队」）；本局中从未出现过的当届真实选手（开局届 roster 里没有他、也不是待登场新秀，如 TI8 开局时 Spirit 在 TI9 的 G / Illidan / 633）按当届真实生涯轨迹的战力 / 天梯作为自由选手加入并签下；
  其余位置用自由选手 / 生成新人补齐；选秀之后（`signFoundedClubRookies`）再签回本届登场、被 AI 选中或落选的真实新秀（阵容已满时放走补位队员，当届真实选手优先）。之后由使命（7.3）继续追逐现实巅峰阵容（如 TI9 成立的 Spirit 追逐 TI10 的 Yatoro / TorontoTokyo / Collapse / Mira / Miposhka，原 TI9 老将逐步被替换）。
- **联赛规模**：未解散战队数保持在 [`team.minTeams` 28, `clubs.maxTeams` 34]——下限由 `ai.aiEnsureRosters` 生成程序化战队补足；已满时只为「重要」俱乐部（当届 TI 正赛队或现实最好名次 ≤ 8）腾位：
  解散一支过气的 AI 俱乐部（虚构组织，或现实中已连续两届以上不在阵容数据中、且从未夺得 TI 的组织；荣誉 < 700 且战力排名在后一半），每季至多 2 支，人类玩家战队永不解散；新闻「【解散】{name} 宣布解散」，队员成为自由选手、教练进入市场、相关报价作废。
- **虚构新组织**：每季 30% 概率成立 1 个（联赛已满时同样由一支过气 AI 俱乐部让出席位，与真实俱乐部共用解散名额、真实俱乐部优先）；资金 = AI 战队资金中位数 × U(0.9, 1.3)，荣誉 150–300，自由选手 / 生成新人组队。
- 新闻「【新战队】{name} 成立」（真实俱乐部列出签回的真实选手与主教练，重要）；界面：DotaPedia 战队信息框「成立」一行（UI.md）。
- 实测（无头模拟，起点 TI1 / 5 / 9 / 12 至 TI16，各 6–8 局）：联赛规模 31–34（均值 33.8）；每季平均成立真实俱乐部约 2 家、虚构组织约 0.1 家、解散腾位约 1.5 支；
  关闭时 TI1 起的联赛始终是 2011 年的那批组织（如 Storm Games Clan 拿下 7 届 TI），开启后 Wings / OG / Secret / Spirit / PARIVISION 等按历史陆续登场。16 个赛季约 2.3 s / 局（联赛多 3–6 队，比关闭时慢 5%–15%）。

### 7.3 俱乐部使命（第十波 #3，`missions.ts`，参数 `CONFIG.missions`）
- **使命**：每个非玩家、未解散的真实俱乐部（`clubIndex.json` 中有该组织）以组建其**现实巅峰阵容**为目标：TI 冠军阵容（同一套五人夺冠最多者，再取最早——OG = TI8/TI9 五人、Spirit = TI10、Liquid = TI7）；
  未夺冠取最好名次的阵容（同名次取当届首发战力之和最高者，如 Secret = TI11 亚军、LGD = TI10 亚军）；从未进入 TI 正赛取首发战力最高的一届。玩家执教的俱乐部（含多人）不设使命；虚构 / 程序化战队没有使命。
- **引进**（不保证成功）：
  - 休赛期转会潮（`shuffle.pursueMissions`，明星去向之前，按战力排名先后）：每队至多 2 名；自由身签下；其他 AI 战队的选手溢价求购（已挂牌的按挂牌成交，否则报价 = 身价 × U(1.3, 1.7)，卖家放人概率 0.5 − 头号选手 0.2 − 卖家自己的使命成员 0.45 + (50 − 归属感)/100 × 0.5）；
    同位置的非使命首发被顶下挂牌（位置调整），为使命成员腾位时可以放走非使命首发；明星求变时使命俱乐部的争夺权重 × 3（`missions.starWeightMult`）；
  - AI 转会窗口（`ai.aiTransferWindow` → `aiPursueMission`，先于其他补强）：季前 1 名、中期 1 名（中期只有 30% 概率向其他 AI 战队求购，自由身总会尝试）；新游戏第一个赛季的季前窗口不引进（与转会潮一致，保留真实开局阵容）；
  - 资金门槛比普通引援宽松（付完费用后余额 ≥ (工资 + 新增工资) × 3）；使命成员对本俱乐部的加盟意愿 +0.1；
  - **人类玩家战队里的使命成员**只会在休赛期收到报价（溢价 1.2–1.5 倍身价，每支玩家战队每个休赛期至多 1 份，35%），玩家在转会市场决定，从不强制带走。成员也可能已退役、尚未出道、在别的使命俱乐部或买不起。
- **留人**：转会潮换人候选分 − 0.8；求变 / 新挑战 / 老将下放 / 低归属感求去的挂牌概率 × 0.3；被挖角时卖家放人概率 − 0.35（AI 窗口的低归属感挖角不挖使命成员）；合同到期时 90% 续约 1–2 季（`missionContractRetention`，TI 结算中合同处理之前）；
  欠薪甩卖与阵容裁剪先动非使命成员（`missionAwareTrim`：非使命替补 → 非使命首发 → 使命成员）。
- **进度与新闻**：`Team.mission`（have k/5、首次 / 最近集齐赛季、集齐状态下夺得的 TI）；在每个 AI 转会窗口结束时刷新（休赛期转会潮与紧随其后的 AI 季前窗口算同一个窗口，只在季前窗口结束时判定，
  避免成员在两段之间离队又被买回时误发「再次集齐」）。新集齐时「【使命】{俱乐部} 集齐 TI{n} 巅峰阵容」；只记录、不发新闻的情形：新游戏第一个赛季开局即已集齐、首次记录进度时（旧存档升级）即已集齐、
  新俱乐部成立时即已集齐（巅峰就是当届阵容，`clubs.foundRealClub` 从成立时记起进度，成立新闻已列出这些选手）；散而复聚的「再次集齐」新闻不标为重要。
  集齐状态下夺得 TI（TI 结算、退役之前）：五人都是夺冠首发 →「【使命】{俱乐部} 以 TI{n} 巅峰阵容夺得 TI{m} 冠军」；有成员坐替补席 →「【使命】集齐 TI{n} 巅峰阵容的 {俱乐部} 夺得 TI{m} 冠军」并注明替补。
  2026-10-10 起 AI 首发优先使命选手（3.1「AI 首发优先级」），使命成员只在两人同位置、或该赛事无法出场时才坐替补席（此前自动排阵只按状态选人，引进的老将常打不上首发）。
- **使命完成**：集齐状态下夺得过 TI 后使命完成——不再优先引进、不再额外留人（成员照常流动）。首版没有这一条时，TI12 起点里集齐 TI10 五人的 Spirit（当时正值巅峰，且有羁绊加成）出现 TI13–TI16 四连冠，使命集齐的冠军占比 42%。
- **平衡实测**（第十波复核，`createNewGame` 新建俱乐部 + 自动处理，至 TI16，各 10 局、种子 1000 + 17k；「集齐」= TI 回合时巅峰五人都是该队签约队员，「首发」= 五人同时是首发；
  对照组只关闭使命（新俱乐部涌现照常），此时仍有少数冠军恰好保留着原班巅峰阵容；「单队最多 TI 冠军」为每局夺冠最多的战队的冠军数，均值 / 最大）：

  | 起点（局数） | 集齐的 TI 冠军占比（其中五人都首发） | 关闭使命时 | TI 时已集齐的战队数（开启 / 关闭） | 单队最多 TI 冠军（开启） | （关闭） |
  |---|---|---|---|---|---|
  | TI1（10） | 16%（24/151；首发 8%） | 8%（12/156） | 3.2 / 1.2 | 4.2 / 8 | 4.4 / 7 |
  | TI5（10） | 13%（15/120；首发 8%） | 8%（9/120） | 3.0 / 1.2 | 3.5 / 6 | 3.5 / 6 |
  | TI9（10） | 8%（6/80；首发 4%） | 5%（4/80） | 2.5 / 1.5 | 2.9 / 5 | 2.3 / 4 |
  | TI12（10） | 24%（12/50；首发 8%） | 12%（6/50） | 5.9 / 3.8 | 1.9 / 4 | 2.1 / 3 |

  使命让集齐巅峰阵容的战队多了约一倍（TI 时 2.5–6 支），集齐者夺冠的占比约翻倍（8%–24%），但大约一半是「集齐但有老将坐替补席」——引进的老成员多已过了巅峰；
  后期起点（TI12 起）巅峰阵容正值当打，约四分之一的 TI 由集齐的战队夺得，夺冠后使命即完成、不再靠留人加成垄断——「有时会成，不会每届都成」。单队多冠王朝开启 / 关闭时同样存在（如 TI1 起同一种子的 EHOME 8 冠 / 7 冠），均值无明显差别。
- 界面：DotaPedia 战队页「使命」章节（目标、k/5 进度、五名成员现在在哪；该届真实 TI 尚未到来时不显示现实成绩，避免剧透），见 UI.md。

### 7.4 俱乐部品牌变迁（第十波 #4，`branding.ts`，数据 `src/data/branding.json`，参数 `CONFIG.branding`）
- 数据：真实组织按届次的名称 / 简称 / 品牌主色（事实性数据，15 个组织：LGD ↔ PSG.LGD、Na'Vi → NAVI、TNC Predator、G2.iG、BOOM Esports、Nigma Galaxy、MOUZ、Thunder Awaken、Soniqs、TSM FTX → TSM、CDEC Gaming，以及 TI15 因禁止博彩赞助商名称而使用的 BoomBoys / TEAM VISION / Iron Wing / HULIGANI）。
  口径：`fromTi` = 新品牌首次在 TI 上使用的届次（与 roster「当届 TI 时」一致）；`teamIds` 列出同一组织在 roster 中的全部战队 id（如 `lgd-gaming` / `psg-lgd`），`sameOrgTeamIds` 可供其他逻辑去重；赛季内的临时更名（如 VP 2022 年 3–9 月的 Outsiders）不计入。
- 套用（`season.startSeason` 开头、选秀与转会新闻之前，`applySeasonBranding`，不消耗随机数）：开局赛季只静默对齐名称 / 简称（roster 个别届次写法不同时以品牌数据为准），不改配色、不发新闻；之后每个赛季对齐名称 / 简称，换届当季才套用该时期给出的配色。
  有变化时发新闻「【品牌更新】{旧名} 更名为 {新名}」（重要）/「【品牌更新】{名称} 启用新视觉」，并记入 `Team.brandHistory`（每队最多 `historyMax` 条；DotaPedia 战队信息框「品牌沿革」）。赛季中途成立的真实俱乐部（clubs.ts `foundRealClub`）直接以当届品牌数据的名称 / 简称成立（如 TI10 的 Nigma 以 Nigma Galaxy / NGX 成立，成立新闻与之一致），之后的赛季不会因对齐而补发品牌更新；`Team.founded.ti` = 当前届次的俱乐部在 `applySeasonBranding` 中也按开局处理（静默）；已解散 / 除名的不更新。
- 界面：风格化队徽按「简称 + 品牌配色」生成，换品牌即换队徽（UI.md「队徽」「本地美术覆盖」）。

### 7.5 第十波整体复核（2026-10-10，新俱乐部涌现 + 使命 + 羁绊同时开启）
无头模拟（`createNewGame` 新建俱乐部作为旁观者、每回合补足其资金与荣誉以免提前结束，只用「下一回合」自动处理，种子 700 + 17k，各 8 局；
「巅峰 5/5」= TI 回合时现实巅峰五人都是该队签约队员，与使命开关无关地直接统计；关闭羁绊时「羁绊」列统计五人同队、本可觉醒的战队）：

|---|---|---|---|---|---|---|---|

| TI5（10） | 28–34 / 33.1 | 2.00 / 0.05 / 1.45 | 10%（8/80；6） | 6% / 11% / 6% | 5% | 0.24 / 1.8 | 3.1 / 5（3.5 / 6） |
| TI9（8） | 30–34 / 33.4 | 1.72 / 0.03 / 1.25 | 9%（6/64；5） | 9% / 13% / 8% | 9% | 0.50 / 2.8 | 2.6 / 3（2.8 / 5） |

- 联赛规模：开局赛季为开局届 roster + 程序化补足到下限（28；TI9 起 roster 本身 29 队 + 玩家 = 30），首季不成立新俱乐部；之后各季 31–34（约 85% 的赛季满 34），上限从未突破；AI 俱乐部从不破产。
- 使命：每局开局后才集齐的使命 2–3.5 个，以集齐状态夺得 TI（使命完成）0.75–1.6 个；巅峰阵容就是开局阵容的强队（TI13 起的 GG / Falcons / Liquid）占了大部分「集齐即冠军」，
  使命让这些阵容更难被拆散，因此 TI13 起占比高于关闭时，但每队夺冠后使命即完成，没有出现靠使命连冠的王朝。早期起点里成立较早、追逐后来巅峰阵容的俱乐部（如 TI6 成立的 OG）在引进过程中累积强援，
  TI5 起 80 届中 OG 夺冠 13 次（关闭使命 3–4 次），但每局夺冠最多的战队冠军数与关闭时相当（只是换了战队），8–10 季的长局每局有 5–7 支不同的冠军。
- 羁绊：TI 回合时全联盟平均激活 0.24–0.81 个，每局解锁 1–3 个；激活羁绊的战队夺得 3%–9% 的 TI，不高于关闭羁绊时本可觉醒的五人组（3%–16%），不主导冠军归属。
- 新俱乐部成立的战队夺得 6%–35% 的 TI（TI5 起最高，主要是 OG / Wings / Liquid 这些现实中的冠军组织），符合「后来成立的真实俱乐部按历史登场」的预期。
- 结论：无需调整数值。

## 8. 游戏结束
- 达到设定的最后一届 TI 结算后 → 生涯总结（TI 冠军次数、其他冠军、荣誉峰值、财务）。目标：至少夺得一次 TI 冠军。
- 荣誉 < 0 → 立即解散，游戏结束。
- 俱乐部全员假赛曝光 → 立即结束（`reason: 'banned'`，专门结局）。
- 资金连续 3 个回合为负或负债超过 6 个回合工资 → 破产，立即结束（`reason: 'bankrupt'`，专门结局，见 3.6）。
- 多人模式：解散 / 全员假赛 / 破产的座位出局转观战（可查看自己的生涯总结），其余玩家继续；全部座位出局或执教期满时游戏结束（见 MULTIPLAYER.md）。
- **生涯总结（`legacy.ts`，类似《文明》）**：每个赛季结算时为人类战队记录 `state.legacyLog[teamId]`（赛季末战力排名、TI 名次、冠军、关键时刻、阵容；出局 / 禁赛时冻结部分赛季）。结算页计算传奇值 = 成就分（TI 冠军逐冠递增、卫冕、亚军、前四、前八、参赛、Major、顶级赛事封顶）+ 赛季实力分（按联盟规模归一，以成就分为上限）+ 声望（荣誉峰值），禁赛折半；
  按同一口径与 `src/data/legacyClubs.json`（31 家真实俱乐部截至 TI15 的 TI 成绩与 Valve Major，事实数据，测试与 tis.json 交叉校验）比较，给出称号（不朽神话 / 三冠王朝 / 两连冠王朝 / 双冠豪门 / 单冠王者 / 亚军之王 / 常青豪门 / 无冕之王 / 一时劲旅 / 默默无闻）、最接近的历史俱乐部、历史排行榜名次、赛季时间线、关键时刻、最佳选手、荣誉与资金曲线、结局叙述。参数见 `CONFIG.legacy`。

## 9. 数据文件约定（`src/data/`）
- `tis.json`：`TiInfo[]`
- `rosters/ti{n}.json`：`RosterFile`（该届 TI 全部参赛队 + 6–12 支未进 TI 的知名队 + 自由选手 + 自由教练）
- `playerIndex.json`：由脚本根据全部 roster 生成（玩家首次出现的 TI、峰值等），用于「真实新秀」在未来赛季登场
- `trajectories.json`：`scripts/build-trajectories.ts` 由全部 `rosters/ti*.json` 生成（选手 id → { TI: { power, mmr, tier } }，含替补与自由选手，同届重复取较高者），供赛季自主成长参照真实生涯轨迹（2.4.2）；roster 变动后需重新生成
- `patches.json`：`PatchInfo[]`
- `heroes.json`：`HeroInfo[]`
- `tournaments/season{n}.json`：`TournamentTemplate[]`
- `branding.json`：真实组织按届次的品牌（名称 / 简称 / 主色 / 队徽辅色 / 事实说明），见 7.4；`tests/branding.test.ts` 校验结构、战队 id 与 roster 的一致性
- `clubIndex.json`：`scripts/build-club-index.ts` 由全部 roster + `legacyClubs.json` + `branding.json` 生成的真实俱乐部（组织）索引：各届品牌 / 荣誉 / 资金 / 队员与位置 / 主教练、首次出现届次、现实巅峰阵容、最好名次（新俱乐部涌现 7.2、俱乐部使命 7.3）；三者任一变动后需重新生成，`tests/clubs.test.ts` 校验一致
- ID 规范：选手/战队/英雄均为小写 kebab-case 英文 slug，跨文件保持一致（如 `miracle`, `n0tail`, `team-spirit`, `natures-prophet`）。

## 12. DotaPedia 百科（统计记录 `stats.ts` / 查询 `pedia.ts`，参数 `CONFIG.pedia`）
- **数据**：`GameState.pedia`（`PediaState`，全局公开数据，非座位私有；多人模式每个座位视图都含完整统计）。只存聚合，不存逐局个人数据（含玩家战队的对局）：
  选手按「赛季 × 战队」分行（局数 / 胜 / K / D / A / MVP / 奖金分成 / 系列赛胜平负）+ 生涯英雄表（赛季末只保留局数最多的 14 个，其余并入「其他」）+ 当前 / 最长连胜 + 巅峰等级；
  战队按赛季分行（系列赛胜平负含弃权、小局胜负、击杀 / 阵亡、时长、奖金俱乐部 / 队员、赛季末荣誉 / 综合排名 / 实力排名 / 阵容 / 主教练）+ 系列赛 / 小局连胜；
  赛事补充记录（冠亚军首发、TI 全部正赛首发、前四名奖金；名称 / 等级 / 全部名次见 `history.tournaments`）；英雄按赛季（出场 / 胜 / K / D / A / 被禁）；单局纪录。
  **单局明细不存**（用户反馈 2026-10-10「单局明细就不存了」）：每局的个人 K/D/A 只累加进上面的聚合与单局纪录（个人击杀 / 助攻 / 阵亡最多、单队 / 双方击杀最多、最长 / 最短对局），
  不再写入 `GameRecord.box`。统计格式 `PediaState.v = 2`；旧存档残留的 box 由 `stats.stripLegacyGameBoxes` 清除——单机读档（`save.importSave`）时即清除，
  多人房间文件在第一次写入统计（v1 → v2 升级）时清除（赛事系列赛、进行中的比赛、多人玩家对决与座位私有数据中的对局），聚合原样保留。
- **记录点**（引擎钩子，人机共用）：`match.simulateGame`（每一局，含 AI 快速模拟）→ `tournament.recordSeriesResult`（系列赛）→ `tournament.finishTournament`（奖金拆分、冠亚军首发）→ `season.settleSeason`（赛季末快照，退役之前）。
- **确定性**：不使用 `rngOf(state)`，每局使用按（存档 id, 对局序号）派生的子随机流；`CONFIG.pedia.enabled` 开关不影响任何比赛结果与主随机序列（测试逐字节比较存档）。
  AI 快速模拟的英雄候选只取决于（日期, 版本）（强度表缺失的英雄按 `heroMetaValue` 补算），进程内多个存档（多人服务器的多个房间）共用缓存互不影响。
  记录钩子全部有异常保护：手工编辑 / 截断的存档导致统计写入失败时只跳过这条统计（不影响比赛与赛事流程，进程内只报告一次）。
- **统计起点**：新游戏（创建统计时全联盟没有任何已赛对局）标记 `PediaState.full = 1`，`overview.complete = true`；旧存档从读档后的下一局开始记录（`since` = 当时的赛季 / 回合）。
- **单局分配**：A 方击杀之和 = killsA，A 方阵亡之和 = killsB；击杀 / 阵亡 / 助攻按位置权重 × 发挥噪声 × MVP 倍数（最大余数法）分配，全队助攻 = 击杀 × U(1.95, 2.65)，每人助攻 ≤ 本队击杀 − 自己的击杀；
  权重按真实 TI 标定（每队击杀占比约 1~5 号位 29% / 28% / 20% / 14% / 9%，阵亡 13%~26%、助攻 15%~23%），总击杀 / 时长按年代标定见 4.4。
  发挥噪声：击杀 σ 0.32，阵亡 0.22、助攻 0.2（`deathNoiseSigma / assistNoiseSigma`：真实比赛的阵亡与助攻在队员之间更平均；按历届 TI 实测，单人阵亡 > 15 约 0.24%、击杀参与率 > 90% 约 4%，三者同用 0.32 时约为 2 倍）。
  有文字直播的对局直接采用直播中的个人击杀 / 阵亡（`LiveContext.kdOut`，与直播文本一致）：直播先按同一张权重表与同口径的发挥噪声算出每人本局的击杀 / 阵亡份额（最大余数法），
  每个击杀再按剩余份额抽取击杀者 / 阵亡者（随机数用量与逐次按权重抽取相同），所以直播的个人数据分布（含尾部）与快速模拟一致——逐次独立按权重抽取会多一层多项分布方差（单人 20 杀以上约为 2 倍、5 号位偶尔 15 杀）。英雄：有 BP 取 BP；AI 快速模拟按招牌英雄（45%）/ 位置适配 × 版本强度候选确定性挑选，同局不重复。
- **历史地位（不必等结束）**：沿用 §8 传奇值口径。战队综合传奇值 = 开局前（现实）成就（起始 TI 之前的真实 TI 名次 `src/data/tiResults.json` 由 `scripts/build-ti-results.ts` 从 roster 生成，
  同组织合并按 `legacyClubs.json` 的 teamIds；Valve Major 按赛事模板匹配所在赛季）+ 本局成就（赛事史 + 赛季末实力排名 + 当季实时实力；人类战队与结算页一致）；
  给出称号、评级、最接近的历史俱乐部、本局全部战队中的名次与历史排行榜名次，并单列「开局前（现实）」。真实俱乐部在本局中就是它自己：
  历史排行榜与「最接近的历史俱乐部」都排除它自己的现实条目（否则 OG 会与「未来的自己」比较、最接近的俱乐部是自己）。
  `legacyClubs.json` 的 teamIds 必须覆盖同组织的改名 / 冠名主队（如 G2.iG = Invictus Gaming），测试按 `tiResults.json` 逐俱乐部校验履历一致。
  选手另有简化版（TI 名次含开局前真实履历、各级冠军、MVP、赛季、巅峰等级）。
  综合传奇值按「开局前 + 本局」合并后的成就重新计分（声望只按当前荣誉峰值计一次、赛季实力上限按合并后的成就），所以不等于「单算本局」（`inGameScore`，人类战队与结算页一致）与「单算开局前」（`preGameScore`，历史俱乐部口径）之和，界面按「单算」标注并说明。
  开局前（现实）只列起始 TI 之前的成绩；俱乐部的现实一句话（`legacyClubs.json` 的 highlight）描述的是完整现实履历，只在该俱乐部的现实 TI / Major 全部早于起始 TI 时显示（TI9 开局的 OG 不显示「TI8–TI9 两连冠」），避免剧透本局尚未发生的历史。
- **查询 API**（纯函数，索引按缓存键复用：统计写入修订号 `stats.pediaRevision()`（含弃权 / 奖金 / 赛季末快照等不产生对局的写入）+ 回合 / 赛事史 + 回合内世界变化（id 计数 / 新闻 / 财务：转会、事件荣誉、训练）；查询不修改存档，测试逐字节校验）：`pediaDashboard`（总览、TI 冠军含开局前现实、排行榜、单局纪录、历史地位榜，可按赛季筛选）、`pediaTeamPage`、`pediaPlayerPage`、
  `pediaTournaments` / `pediaTournament`、`pediaHeroStats` / `pediaHeroTrend`、`pediaSearch`、`pediaLegacyBoard` / `pediaTeamLegacy`、`pediaPlayerStanding`。
- **实测**（`tests/stats.test.ts`，TI1 → TI16 接管 Na'Vi；体积按同一种子「记录开 / 关」两份完整存档比较）：每局记录约 15µs（多次运行取最小值，全流程约 +10% 耗时）；
  存档 10 个赛季约 +18%（+400~410 KB / 2.6~2.7 MB）、16 个赛季约 +16%~17%（+630 KB / 4.3~4.5 MB），增量全部是 pedia 聚合（改动前含逐局 box：+18.8% / +19.1%，16 季 +702 KB 其中 box 约 74 KB）。
  去掉逐局 box 节省（TI9 起接管 OG 3 个赛季实测，按旧格式每局 10 行 [选手, 英雄, K, D, A] 还原）：赛季初约 63~65 KB（保留的上赛季本方 / 进行中对局约 220 局，−4.5%）、
  赛季中回合间峰值约 136 KB（2.3 MB 存档的 −5.6%）、游戏结束时约 112 KB（−4.5%）；新建俱乐部峰值约 60 KB（640 KB 存档的 −8.6%）。旧存档读档时（`save.importSave`）即清除残留的 box；多人座位视图 +10%~11%（2 名玩家，3 个赛季约 +186 KB / 1.8 MB）。旧存档（无统计）从下一局开始记录（`overview.complete = false` 时界面提示统计起点）。

- **界面**（规范见 UI.md「DotaPedia」）：侧栏「DotaPedia」= 总览 | 战队 | 选手 | 赛事 | 英雄 | 羁绊图鉴（见 3.7），词条之间互相链接，选手 / 战队弹窗有「DotaPedia ›」入口；
